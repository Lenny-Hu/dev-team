# 软件开发团队（software-dev-team）

在 ZCode 里召唤一支像专家团一样的软件开发团队：**交付总监**带队，产品经理定需求、架构师做设计+拆任务、工程师批量并行实现代码、QA 验证质量；小需求支持快速模式。

## 组成

| 组件 | 说明 |
| --- | --- |
| `commands/dev-team.md` | 召唤入口（完整模式）：`/dev-team <需求描述>` |
| `commands/dev-team-fast.md` | 召唤入口（快速模式）：`/dev-team-fast <小需求描述>` |
| `skills/software-dev-team/SKILL.md` | 交付总监手册：召唤协议、模式选择、放行与验收标准 |
| `skills/software-dev-team/references/` | 五个角色的职责文档（交付总监/产品经理/架构师/工程师/QA） |
| `workflows/software-dev-team.dwf.ts` | 团队流水线：需求 → 设计拆任务 → 按依赖批次并行实现 → 检查+QA 验收 → 交付报告 |

## 两种模式

- **完整模式（full）**：产品经理出 PRD → 交付总监审校 → 架构师设计并拆任务 → 交付总监审校 → 工程师按依赖批次并行实现、逐任务质检 → QA 跑项目自带检查并对照 PRD 逐条验收 → 交付总监终验并汇总交付报告。
- **快速模式（fast）**：技术负责人（产品+架构二合一）一次产出需求与方案 → 交付总监快审 → 工程师实现 → QA 以项目检查为主验收 → 交付总监汇总。跳过逐任务质检。

## 工作流产出

- `.dev-team/prd.md`：需求文档（范围、验收标准、非目标、假设）
- `.dev-team/design.md`：技术方案与任务拆分
- 交付报告（artifact，含任务完成情况、检查命令与退出码、验收结论、未覆盖项）
- 任务看板（artifact.board，实时查看每个任务处于 实现中/已验证/需修复/已完成）

## 质量约定

- 项目自带的检查命令（npm test/build/lint、pytest、cargo test/build）由工作流统一执行，QA 不重复跑；
- 每轮修复由交付总监分诊、限定两轮，避免空转；
- 结论分清「已验证」（有独立子代理或确定性检查确认）与「未覆盖」（明说为什么没查）；
- 任何角色不得谎称跑过没跑的命令；修不过去时升级，不造假。

## 安装（本地测试市场）

市场根目录：`D:\web\dev-team\zcode`（含 `marketplace.json`）。
在 ZCode 中：插件市场 → 添加 → 添加插件市场，粘贴上述目录；然后在「个人」中找到「软件开发团队」安装。
