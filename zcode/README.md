# 软件开发团队 · ZCode 插件交付说明

本目录是一个 ZCode 本地插件市场的根目录，内含「软件开发团队」插件源码：在 ZCode 里召唤一支由**交付总监**带队的研发专家团——产品经理定需求、架构师做设计+拆任务、工程师批量并行实现代码、QA 验证质量，小需求支持快速模式。

## 交付内容

```text
zcode/                                   ← 本地测试市场根目录（粘贴到 ZCode 的就是它）
├── marketplace.json                     市场清单（市场名 dev-zcode-215ecc2f）
└── software-dev-team/                   插件源码（software-dev-team，版本 0.1.0）
    ├── .zcode-plugin/plugin.json        插件清单
    ├── commands/
    │   ├── dev-team.md                  召唤入口：完整模式 /dev-team
    │   └── dev-team-fast.md             召唤入口：快速模式 /dev-team-fast
    ├── skills/software-dev-team/
    │   ├── SKILL.md                     交付总监手册：召唤协议、模式选择、放行与验收标准
    │   └── references/                  五个角色的职责文档
    │       ├── delivery-director.md       交付总监（团队 Lead）
    │       ├── product-manager.md         产品经理
    │       ├── architect.md               架构师
    │       ├── engineer.md                工程师
    │       └── qa.md                      QA
    ├── workflows/
    │   └── software-dev-team.dwf.ts      团队流水线（完整/快速双模式）
    └── README.md                        插件自身说明
```

两种模式的流水线：

- **完整模式**：产品经理出 PRD → 交付总监审校 → 架构师设计并拆任务 → 交付总监审校 → 工程师按依赖批次并行实现、逐任务质检 → QA 跑项目自带检查并对照 PRD 逐条验收 → 交付总监终验并汇总交付报告。
- **快速模式**：技术负责人（产品+架构二合一）一次产出需求与方案 → 交付总监快审 → 工程师实现 → QA 以项目自带检查为主验收 → 交付总监汇总。跳过逐任务质检。

## 安装步骤

1. 打开 **插件市场 / Plugin Marketplace** → **添加 / Add → 添加插件市场 / Add Plugin Marketplace**。
2. 粘贴市场根目录：`D:\web\dev-team\zcode`（就是本 README 所在的目录），点击添加。
3. 添加成功后进入 **个人 / Personal**，找到「软件开发团队」（版本 0.1.0），点击 **安装 / Install**。
4. 安装后可在 **设置 → 插件 / Settings → Plugins** 管理启用状态。

后续更新：在市场源里点该市场的**刷新**，再到「个人」里对插件点**更新**；源码改动不会热更新，必须走这两步。

## 使用方式

安装后新建任务，在输入框直接召唤：

- `/dev-team <需求描述>` —— 完整模式，适合涉及多个模块、要改多处代码、有集成风险的需求；
- `/dev-team-fast <需求描述>` —— 快速模式，适合单一目标、一两个文件能搞定的小需求。

拿不准就用完整模式。运行期间主代理以交付总监身份工作：审校不过会打回修订（最多两轮），子代理遇到阻塞会向你提问，任务看板实时显示每个任务处于 实现中 / 已验证 / 需修复 / 已完成。

## 验收方式

安装后新建任务，输入：

```text
/dev-team 做一个本地待办清单 CLI：支持添加、列出、完成待办，数据存在 JSON 文件里，带单元测试
```

预期可观察结果：

1. 工作流按九个阶段推进：需求界定 → 总监审校 → 设计拆任务 → 总监审校 → 并行实现 → 逐任务质检 → 项目检查 → QA 验收 → 终验交付；
2. 任务看板逐个任务翻状态，同批任务并行推进；
3. 仓库中生成 `.dev-team/prd.md`（需求与逐条可核对的验收标准）和 `.dev-team/design.md`（方案与任务拆分）；
4. 结束产出交付报告卡片：各任务完成情况、检查命令与退出码、逐条验收结论、未覆盖项；
5. 结论分清「已验证」与「未覆盖」——没跑的检查会明说，不会装作没问题。

小需求可再试一次快速模式对比耗时：

```text
/dev-team-fast 写一个华氏度转摄氏度的命令行脚本，带 pytest 测试
```

## 备注

- `.dev-team/` 是团队每次运行重新生成的产出，已在仓库 `.gitignore` 中忽略；需要留存需求文档溯源可自行放开。
- 工作流脚本的完整类型检查在首次 `/dev-team` 提交时由 ZCode 工作流编译器完成；若收到编译诊断，按提示修正 `workflows/software-dev-team.dwf.ts` 后重新提交即可。
- 本目录为本地测试市场，不等于公开发布；换机器使用需重新执行上面的添加步骤。
